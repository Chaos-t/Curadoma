## What this project is

Marketing website for **Cura Doma**, an ambulatory care service (ambulanter Betreuungsdienst) in Hameln, Germany. Single-page React app with multiple routes, **pre-rendered to static HTML at build time**; all user-facing copy is German. The site exists to (a) explain services covered under §45a/§45b SGB XI to families, (b) capture contact requests, (c) capture job applications, and (d) give the operator a password-protected **in-place content editor + backoffice** under `/admin`. Everything server-side lives in one Supabase Edge Function that mails the operator over Strato SMTP.

The whole frontend was originally generated by **Figma Make** and committed largely as-is. That history matters when reading code.

**Second reference doc:** [docs/superpowers/admin-verwaltung-referenz.md](docs/superpowers/admin-verwaltung-referenz.md) — how the editor/backoffice was built, why each decision was made, plus a dated changelog (§11). **Rule: every change to `/admin`, the editor, or the Edge Function gets an entry there.** This file (CLAUDE.md) is the map; that file is the history.

## Quick start

```
npm install
npm run dev      # vite, defaults to http://localhost:5173 (no pre-rendering in dev)
npm run build    # vite build → dist/, then node scripts/prerender.mjs
```

No test runner, no linter, no formatter, no `tsc` step. Vite transpiles TSX via `@vitejs/plugin-react` without type-checking. **There is no `tsconfig.json`** — adding one would be a deliberate change, not a fix. Type errors show up only at runtime (or when an IDE happens to type-check). Treat this as a constraint to work around, not a bug to fix unbidden.

The one thing that *is* unit-tested: the pure server helpers, via Node's built-in runner (no Deno needed locally):

```bash
node --test "supabase/functions/make-server-ec6100a6/admin_util.test.ts"
```

## Stack

- **React 18.3** + **react-router 7** — routes are plain data in `src/app/routes.tsx`; the browser router is built in `src/app/router.ts`, the static one in `src/entry-server.tsx` (see "Pre-rendering" below)
- **Vite 6** (`vite.config.ts`) with the Tailwind v4 Vite plugin
- **Tailwind CSS v4** — config-less, source globs declared in `src/styles/tailwind.css` via `@source`
- **Radix UI primitives** (full set) and a complete **shadcn/ui** copy under `src/app/components/ui/` — see "shadcn is unused" below
- **Lucide React** for icons (always `strokeWidth={1.5}` in this codebase — match the existing look)
- **Supabase Edge Function** (Deno + Hono) under `supabase/functions/make-server-ec6100a6/` — forms, appointments, reviews, Instagram, content editor, backoffice. One function, one trust boundary.
- **Strato SMTP** for transactional email — a hand-rolled single-part `text/html` SMTP conversation inside the function (see the email gotcha under "Backend"). Credentials live in the Function env, never in the bundle.

A pile of additional deps (`motion`, `react-hook-form`, `recharts`, `embla-carousel`, `cmdk`, `vaul`, `react-dnd`, `react-slick`, `react-day-picker`, `next-themes`, `three`, `@mui/*`, …) come from the Figma Make starter and are **mostly unused**. Don't assume "if it's in package.json it's wired in." Grep before importing.

## Styling conventions — read before editing any page

The pages were generated by Figma Make and **bypass the design system that was scaffolded alongside them**. Reading the codebase top-down is misleading; here is what's actually true:

1. **Colors are hardcoded hex literals** in arbitrary-value Tailwind classes (`bg-[#6FD3D1]`, `text-[#5F6B73]`, `border-[#E5F4F5]`). Match the existing palette when adding UI:

   | Role                   | Hex        | Where it shows up                                |
   |------------------------|------------|--------------------------------------------------|
   | Brand teal (decor)     | `#6FD3D1`  | Icons, borders, fills — **never text**           |
   | Teal, text/buttons     | `#0F7C77`  | Links, CTAs, button surfaces (WCAG-safe)         |
   | Teal on mint           | `#0E6E6A`  | Text/badges on `#DFF7F8`                         |
   | Brand teal (hover)     | `#5BC2C0`  | Link hover                                       |
   | Mint surface           | `#DFF7F8`  | Pills/chips, soft backgrounds                    |
   | Mint border / glow     | `#BFEAF2`  | Borders, blur orbs, selection                    |
   | Card border            | `#E5F4F5`  | Card outlines, dividers                          |
   | Page background        | `#F8FEFF`  | Body                                             |
   | Body text              | `#111111`  | Headings, primary copy                           |
   | Muted text             | `#5F6B73`  | Secondary copy, small labels                     |
   | Editor red             | `#d7120a`  | "editable" outlines, destructive actions         |

   **Contrast rule (2026-07-20 sweep, don't regress it):** `#6FD3D1` on white is only ~1.6:1, so it was removed from *every* text/button surface in favour of `#0F7C77` / `#0E6E6A`; `#9AA3A8` small text became `#5F6B73`. `#6FD3D1` deliberately stays for icons, borders and fills — contrast rules don't apply there, and it keeps the brand look. The audience is seniors; legibility is a hard requirement.

2. **Fonts are set via inline `style` props**, not Tailwind utilities. The pattern is:
   ```tsx
   const jakarta = { fontFamily: "'Plus Jakarta Sans', 'Plus Jakarta Sans Fallback', sans-serif" };
   <h1 style={jakarta}>…</h1>
   ```
   Body text inherits Inter from `Layout.tsx`'s root `<div style={{ fontFamily: "'Inter', 'Inter Fallback', sans-serif" }}>`. Cormorant is used only by the logo wordmark.

   **Always keep the `… Fallback` entry in the stack.** Those are metric-matched `@font-face` rules in `src/styles/fonts.css` (`ascent-override`/`size-adjust` computed from the real woff2 metrics) that make Arial reflow-identically to the real font while it loads. They cost zero bytes and were the fix for the last remaining CLS. Dropping them from a font stack silently brings the layout shift back.

   Fonts are **self-hosted** from `public/fonts/` — not Google Fonts (CLS + no IP transfer to Google). Adding a weight means adding the woff2 file *and* an `@font-face` block; the two preloads in `index.html` cover the above-the-fold faces.

3. **`src/styles/theme.css` defines shadcn tokens (`--primary`, `--card`, `--ring`, `oklch(...)`, etc.) — but page code never references them.** It's vestigial. Do not "tidy" pages by switching to `text-primary` etc.; that token currently resolves to `#030213` (near-black), which would visibly break the design. Either leave the token wall intact, or change it deliberately and migrate the whole site at once. Don't half-migrate.

4. **`src/app/components/ui/` is a complete shadcn/ui drop-in (`button.tsx`, `card.tsx`, `dialog.tsx`, … 40+ files) — and nothing in `src/app/components/*Page.tsx` imports from it.** Pages use raw `<button>`/`<div>` + Tailwind. Before reaching for `<Button variant="…">`, decide: do I want to introduce shadcn here (and accept it'll look out of place against hand-rolled buttons), or stay consistent with the rest of the page? Default to **stay consistent**.

5. **Animations** live as inline CSS blocks at the bottom of components, named with a `cura` prefix (`curaPartnerMarquee`, `curaFadeIn`). Tailwind classes reference them via `motion-safe:animate-[curaFadeIn_900ms_ease-out_both]`. Keep the prefix to avoid collisions, and always give reduced-motion an escape hatch.

   **Emit them through `<Css>{…}</Css>`, never `<style>{…}</style>`** — see "Pre-rendering" below. Prefer animating `transform`/`opacity` only (compositor-friendly); a `clip-path` and a `0% { opacity: 0 }` hero keyframe were both real Lighthouse findings.

6. **Lucide icons** use light strokes — `strokeWidth={1.5}` in the vast majority of cases, and `1`–`1.3` for a handful of large decorative icons (e.g. [DemenzPage.tsx:147](src/app/components/DemenzPage.tsx#L147), [EntlastungPage.tsx:162](src/app/components/EntlastungPage.tsx#L162)). Default Lucide is 2 and looks heavier than the rest of the UI — match neighbouring icons rather than picking arbitrarily.

## TypeScript: there is no tsconfig

`.tsx` files are transpiled by Vite's esbuild without type-checking. There is no `tsc` step in `package.json`. Two consequences:

- A change that breaks types will **build and run**; you'll only catch it when the page errors at runtime or your editor flags it. Verify by exercising the route in the browser, not by running `tsc`.
- Don't be surprised by absolute-looking imports such as `from "/utils/supabase/info"` (the leading slash makes it a Vite-resolved root-relative path, working because Vite's project root is the repo root). Both [src/app/components/KontaktPage.tsx:4](src/app/components/KontaktPage.tsx#L4) and [src/app/components/KarrierePage.tsx:4](src/app/components/KarrierePage.tsx#L4) use it. The autogenerated comment on `utils/supabase/info.tsx` says DO NOT EDIT — leave the path style alone unless changing both call sites.

The `@` → `src` alias is configured in `vite.config.ts` but not currently used in source. Either style is fine; match nearby code.

## Pre-rendering (SSG) + hydration — read before touching render code

Since 2026-07-27 the build renders **every route to real HTML**. Reason: the site was 100 % client-rendered and Lighthouse measured 4.710 ms "render delay" on mobile for the LCP element (the hero *text*) at 0 ms load time — nothing was being waited on except React.

How it fits together:

- [scripts/prerender.mjs](scripts/prerender.mjs) builds an SSR bundle from [src/entry-server.tsx](src/entry-server.tsx), renders each path in `SEO_BY_PATH`, injects the markup into `<div id="root">` and route-specific meta into the head, and writes `dist/<route>.html`. A route that fails to render falls back to the empty shell (site still works, just without pre-rendered content).
- [src/main.tsx](src/main.tsx) calls `hydrateRoot` when `#root` already has content, else `createRoot`.
- `dist/404.html` is deliberately the **empty shell**. A copy of the pre-rendered homepage would flash homepage content on every unknown URL (incl. `/admin` and operator-created pages) before the router settles.

Three traps that already cost a debugging round — don't re-introduce them:

1. **`<style>{`…`}</style>` breaks hydration** as soon as the CSS contains `"`, `&` or `<`: `renderToString` escapes the text (`&quot;`), the browser does *not* decode inside `<style>`, server and client markup differ, React aborts hydration (error #418) and re-renders everything. **Always use `<Css>{`…`}</Css>`** ([Css.tsx](src/app/components/Css.tsx)).
2. **No `window` reads during the first render.** `useIsMobile` in [CityRoadmap.tsx](src/app/components/CityRoadmap.tsx) starts at `false` and corrects in an effect; `BackgroundScene` uses a media query instead of a JS breakpoint. A first render that differs from the served HTML aborts hydration.
3. **`createStaticRouter` must get `dataRoutes` from `query()`**, not the raw `routes` array — otherwise the `lazy` routes stay unresolved and subpages render empty. And `StaticRouterProvider` needs `hydrate={false}`, or it appends an extra `<script>` and `#root` has a different child count than on the client.

Because of this, `src/app/routes.tsx` must stay importable in Node: it holds route **data only**; `createBrowserRouter` lives in `src/app/router.ts`.

## Backend (Supabase Edge Function + Strato SMTP)

Single function under [supabase/functions/make-server-ec6100a6/index.ts](supabase/functions/make-server-ec6100a6/index.ts), deployed to:

```
https://${projectId}.supabase.co/functions/v1/make-server-ec6100a6/<route>
```

Deploy:

```bash
npx supabase functions deploy make-server-ec6100a6 --no-verify-jwt --project-ref gjcleedoysndaagtsqjb
```

⚠️ **`--no-verify-jwt` is mandatory** (also pinned in `supabase/config.toml`): `/appointment-action` is opened straight from an email with no auth header and would otherwise 401.

Routes:

- `GET  /health` → `{status:"ok"}`
- `POST /contact-messages` — body: `{name, email, phone?, subject?, message, page_source?, consent_privacy}`. Stores under `contact_message:<uuid>` in `kv_store_ec6100a6`, then emails the operator. Validation returns `422 {error, fields}` with German field-level messages.
- `POST /job-applications` — body: career form fields **plus `cv_base64` + `cv_mimetype`** (the frontend reads the picked file as a base64 data URL). Stores under `job_application:<uuid>`. The CV **is now uploaded** to a **private Supabase Storage bucket `bewerbungen`** at `<id>/<sanitized-filename>` (auto-created on first use; ≤5 MB; pdf/doc/docx/png/jpg only), and the notification email carries a **90-day signed download link**. CV upload is **fail-soft** — a failure never blocks the application (it's stored + emailed regardless, with a "could not store" note). The record keeps `cv_path`. *(History: previously the bytes were dropped client-side and only the filename was sent — fixed 2026-06-23.)*

  **Email rendering gotcha (applies to EVERY mail this function sends):** `sendEmail` speaks SMTP by hand and builds a **single-part `text/html`** message — no multipart, no boundary (`buildRawMessage`). This is not an accident to be "cleaned up": mailer libraries (denomailer 1.6.0 was the original) wrap the body in `multipart/alternative`/`mixed` as soon as there is a second part or an attachment, and those boundaries + quoted-printable leak as raw text into Strato webmail (recipient sees `--message100 … Fr=c3=bchester …`). So: **no text part, no attachments.** That's also why the CV travels as a Storage link. (The `text:` field in the `sendEmail` options is accepted and ignored.)
- **Appointment booking** (3 routes; UI at `/termin` — **currently disabled**, see Routing; config mirrored in [src/lib/booking.ts](src/lib/booking.ts) ↔ `APPT_SERVICES`/`APPT_SLOTS` in the function — keep in sync):
  - `POST /appointments` — body `{service, date_iso, time, name, phone, email, message?, consent_privacy, website?(honeypot)}`. Validates service/date(Mon–Fri, not past)/time against whitelists; honeypot + per-IP rate limit + daily cap. Rejects a slot already **confirmed** → `409 slot_taken` (two *pending* requests for the same slot are allowed, like de Vries). Stores `appointment:<uuid>` `{status:'pending', token, …}` in KV. Sends operator mail (with confirm/decline links) + visitor "received" mail. Fail-soft on mail.
  - `GET  /booked-slots` → `{slots:[{date,time}]}` — only **confirmed**, future slots, **no PII** (privacy-by-design; powers the greyed-out slots in the UI).
  - `GET  /appointment-action?token=…&action=confirm|decline` — operator action opened **from an email with no auth header**. ⚠️ **The function MUST be deployed `--no-verify-jwt`** or this 401s. Token regex-validated; idempotent state machine (`pending`→`confirmed`/`declined`); on confirm re-checks the slot is still free (race guard); sends the visitor a confirmed/declined mail; **302-redirects** to `${SITE_URL}/termin-status?s=…` (works as an SPA deep link via the `404.html` fallback). Optional secrets: `APPT_TO` (recipient; falls back to `JOB_TO`/`MAIL_TO`/`SMTP_USER`), `SITE_URL` (default `https://curadoma.de`). Spec: [docs/superpowers/specs/2026-06-23-terminbuchung-design.md](docs/superpowers/specs/2026-06-23-terminbuchung-design.md).
- `GET  /reviews` — returns `{reviews, rating, total, placeUrl, cached, stale}`. Two-stage Google Places call: `findplacefromtext` with `PLACE_DISCOVERY_QUERY = "Cura Doma Hameln"` + a 5 km locationbias, verified to actually contain "cura doma" (a competitor named *curahumana* used to win), with a Text-Search fallback; cached 7 days under `discovered_place_id_v2`. Then `place/details`, cached 6h under `cache:reviews:<placeId>`. `GOOGLE_PLACE_ID` overrides discovery. Google caps reviews at 5 per call — upstream limit, not ours.
- `GET  /instagram-posts` — returns `{posts, cached, stale}`. Instagram Graph API `v18.0/{ig-id}/media`; cached 30 min in KV. Long-lived tokens last 60 days — refresh via the Graph API before expiry.

  **Both of these answer `200` with an empty list when unconfigured or broken** (`{reviews: [], unavailable: true}` / `{posts: [], disabled: "not_configured"}`), *not* 4xx/5xx. That is deliberate: the clients fall back / hide themselves anyway, while a 5xx produced a red console error on **every** page ("Browserfehler in der Konsole protokolliert" in Lighthouse). The real reason stays in the server log and in the response body. Don't "fix" this back to 503.
- **Content editor + structure** (public reads, authenticated writes — see "Content editor"):
  - `GET  /site-content` → `{content:{[id]:string}}` — saved text/image overrides (`{}` until first save).
  - `POST /site-content/save` — `{password, action:"save"|"restore"|"__check", overrides?, rich?}`. `__check` is what the login form uses. Password constant-time vs `EDIT_PASSWORD`; per-IP + global rate limit (bumped on failure, **fail-closed**); id `^[a-z0-9.-]{1,64}$` + length caps; `503` when the secret is unset. **Every stored value is `sanitizeRich`'d unconditionally** (escape-first allowlist `strong/b/em/i/br/a` + safe href) — do NOT gate sanitization on the client `rich` flag; the client renders overrides via `dangerouslySetInnerHTML`. Previous state pushed to `site_content:history` (≤20) for `action:"restore"`.
  - `POST /site-content/image` — `{password, id, dataBase64}`. Magic-byte sniff (JPG/PNG/WebP), ≤3 MB; stored Content-Type derived from the **sniffed** bytes, never the client mimetype (blocks image/HTML-polyglot stored-XSS in the public bucket); uploaded to the public bucket `site-content` as `img/<id>-<ts>.<ext>`; returns the public URL.
  - `GET /zones` + `POST /admin/zones/save` — per-zone ordered lists of item keys (structure only, no HTML) → `zones:current`.
  - `GET /pages` + `POST /admin/pages/save` — operator-created pages `{slug,label,inMenu}` → `pages:current`. Slug regex + `RESERVED_SLUGS` guard.
  - `GET /blocks` + `POST /admin/blocks/save` — typed content blocks `{k,t,href?,align?}` per area → `blocks:current`. Button `href` runs through `safeHref`.
  - `GET /seo` + `POST /admin/seo/save` — per-route title/description/OG-image overlay → `seo:current`. Plain text only (tags stripped), capped; OG image must be absolute http(s).
- **Backoffice** (all POST, all behind `adminGate`; `type ∈ {contact,job,appointment}`):
  `POST /admin/list` · `/admin/update` · `/admin/delete` · `/admin/cv-url` (10-min signed link) · `/admin/export` (CSV) · `/admin/media/list` · `/admin/media/delete` · `/admin/media/restore`. Details + the security model: [docs/superpowers/admin-verwaltung-referenz.md](docs/superpowers/admin-verwaltung-referenz.md) §4/§7.

Validation helpers for zones/pages/blocks/SEO live in [admin_util.ts](supabase/functions/make-server-ec6100a6/admin_util.ts) — **pure and import-free on purpose** so `node --test` can run them without Deno. Put new pure logic there, with a test.

Cache pattern (`cachedFetch<T>` in index.ts): get from KV → if fresh return → else hit upstream → write to KV → return. On upstream failure with a stale cache: serve stale and flag `stale: true`.

Auth model: anonymous clients call POST with the public anon key in `Authorization: Bearer …`. Every write to editor/admin routes carries the password in the body and is checked **server-side** (`adminGate`: secret set? → rate limit (fail-closed) → constant-time compare → 600 ms delay + 401 on failure). Reading/updating KV rows needs the service-role key, which exists only in the Function env. **The frontend is not a security boundary** — someone can force edit mode in DevTools, but without the password nothing saves.

Email sending:
- Sender is `MAIL_FROM`, default `Cura Doma <SMTP_USER>`. Strato rejects foreign senders — keep the From on the authenticated mailbox.
- Recipients come from secrets with fallback chains: contact `CONTACT_TO → MAIL_TO → SMTP_USER`, jobs `JOB_TO → MAIL_TO → SMTP_USER`, appointments `APPT_TO → JOB_TO → MAIL_TO → SMTP_USER`.
- Without `SMTP_USER`/`SMTP_PASS` the endpoint still returns `201` and stores the row, but the response carries `email_sent: false` + `email_error`. That's a config issue, not a code bug.
- A global daily cap (`MAIL_DAILY_MAX`, default 200) bounds outbound mail regardless of source IP.

Supabase Edge Function secrets (Dashboard → Edge Functions → make-server-ec6100a6 → Secrets):
- `SMTP_USER` / `SMTP_PASS` — Strato mailbox login (required for any mail to go out)
- `SMTP_HOST` *(optional)* — default `smtp.strato.de`; `SMTP_PORT` *(optional)* — default `465` (implicit TLS; `587` = STARTTLS)
- `MAIL_FROM` *(optional)* — sender header, default `Cura Doma <SMTP_USER>`
- `CONTACT_TO` / `JOB_TO` / `APPT_TO` / `MAIL_TO` *(optional)* — recipients, see fallback chains above
- `MAIL_DAILY_MAX` *(optional)* — global daily send cap, default 200
- `SITE_URL` *(optional)* — redirect target for `/appointment-action`, default `https://curadoma.de`
- `GOOGLE_PLACES_API_KEY` — server-side key with Places API enabled (Find Place + Place Details)
- `GOOGLE_PLACE_ID` *(optional)* — Place ID override; only if auto-discovery picks the wrong listing
- `INSTAGRAM_ACCESS_TOKEN` — long-lived Page access token (Meta Graph API; 60-day TTL)
- `INSTAGRAM_BUSINESS_ACCOUNT_ID` — numeric IG Business/Creator account ID
- `EDIT_PASSWORD` — editor/backoffice password (16+ chars). **The only access control** for editing and for all PII in `/admin/*`. Until it's set, those routes return `503` and editing is disabled site-wide (the public site is unaffected). Set via `supabase secrets set EDIT_PASSWORD=… --project-ref gjcleedoysndaagtsqjb`.
- `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` — injected by the platform; used for KV + Storage.

Missing config never breaks the public site: `GoogleReviews` falls back to [src/lib/reviews-data.ts](src/lib/reviews-data.ts), `InstagramFeed` hides itself entirely, the editor refuses to save.

The committed `utils/supabase/info.tsx` carries `projectId` + the **anon** key. That is intentional and safe (anon keys are designed to be client-visible). Do not move it to env vars — Figma Make regenerates this file, and breaking the contract will lose changes on the next pull.

The form pages submit `fetch(...)` directly. They show a success state on `2xx`, surface `data.fields` as inline field errors on `422`, and a German fallback message otherwise. Match this pattern for any new form.

## Content editor + backoffice (`/admin`)

`/admin` → password → **Verwaltung** dashboard: inboxes for Anfragen / Bewerbungen / Termine (status, internal note, archive, delete, CV download, CSV export), Mediathek, Seiten & Menü — plus **"Seite bearbeiten"**, which drops the operator into an **in-place edit mode** on the live site (red-dashed outlines; click text to type, click an image to replace it; left edge-panel with Speichern / Verwerfen / Rückgängig / SEO / Hilfe / Verlassen). Saves are **instant-live** on the next load — no rebuild, no GitHub. Built à la the de-Vries CMS, adapted to React.

Docs: [admin-verwaltung-referenz.md](docs/superpowers/admin-verwaltung-referenz.md) (build reference + changelog), specs `docs/superpowers/specs/2026-07-01-inhalts-editor-design.md` and `2026-07-18-admin-panel-ausbau-design.md`, plans + the 558-field content inventory under `docs/superpowers/plans/`.

**Mental model (read before touching editor code):**
- **Defaults live IN THE CODE.** Editable content is wrapped: `<Editable id="page.section.field" as="h2" style={jakarta}>Default text</Editable>` and `<EditableImage id="…" src={img} alt="…" />`. The `children`/`src` IS the fallback — if Supabase is unreachable the site renders the code version. **Never delete the default text when editing the JSX; it is the content.**
- **Overrides (only changed fields) live in Supabase KV** (`site_content:current`), fetched once at startup by `ContentProvider` ([src/lib/content.tsx](src/lib/content.tsx)) and layered over defaults via `get(id)`. Only changed fields flash to the new value on load. Same overlay pattern for `zones:current`, `pages:current`, `blocks:current`, `seo:current`.
- **Edit mode is IN-MEMORY app state — never `sessionStorage`.** `AdminProvider` ([src/lib/admin.tsx](src/lib/admin.tsx)) keeps the password in a `useRef` after `/site-content/save {action:"__check"}` returns 200; the dashboard calls `content.enterEditMode(pw())`. A reload logs you out. (A `sessionStorage.cd_edit` flag was the earlier design and was a bug: it survived reloads and could simply be set in DevTools.) The password is never persisted, logged or put in the DOM.
- **`<Editable>`** ([src/app/components/editor/Editable.tsx](src/app/components/editor/Editable.tsx)) in edit mode = `contentEditable`, seeded ONCE from the committed value (`getStored`, never live `pending`) so React doesn't fight the cursor; `onClick` preventDefault so editable labels inside `<Link>`/`<a>` don't navigate. Overrides always render via `dangerouslySetInnerHTML` of the **server-sanitized** value (plain + rich alike → no double-escape, no XSS).
- **Structure vs. content.** Order/existence of repeated items lives in validated *zones* (`Zone.tsx`, `EditableList.tsx`); typed *blocks* (text/title/image/button/card/quote/divider) live per area in `BlockArea.tsx` + the radial `BlockPalette`. Both store **metadata only** — every piece of text still flows through the sanitized `<Editable>` pipeline. `PageBlocks.tsx` adds such an area to the bottom of the fixed pages; `DynamicPage.tsx` is built entirely from one.
- **`shared.*` = site-wide SSOT.** Contact data (phone/email/address/hours) and menu/footer labels use `shared.*` ids via [src/app/components/editor/Shared.tsx](src/app/components/editor/Shared.tsx) — `PhoneText` / `EmailText` / `AddressBlock` / `HoursText`. One edit updates every occurrence, and these components DERIVE the `tel:`/`mailto:` href from the (editable) value. **When adding contact data anywhere, use these components — never hardcode the number/email/address or its `href`** (that reintroduces the drift the SSOT prevents).
- **Editor UI is lazy-gated.** `EditorChrome`, `SeoPanel` and `BlockPalette` are only imported once `editMode` is true — and the condition sits **before** the render, otherwise `React.lazy` fetches the chunk for every visitor anyway.

**Wrapping rules (when making content editable):** only text + content images are editable — structure, routes, animations, class names stay byte-identical. A hero H1's colored `<span>` stays structural; the text inside is a SEPARATE `<Editable>` (split — never nest markup inside Editable content). Template/runtime variables (`{JOB_TITLE}`, `{count}`, `{form.*}`) are NOT wrapped. `.map` items get indexed ids (`home.services.0.title`). `rich` only for genuine `<strong>`/`<em>`. Icons and `to=`/`href=` never change. The Axion-Studio credit in the footer is deliberately NOT editable.

**Two data-loss traps already hit once** — don't undo the fixes: (1) a fetch helper that swallows errors into `[]` (the old `pagesList`) let the next save overwrite the stored pages with an empty list — these helpers **throw** now, and `AdminPages` never saves before `structureLoaded`. (2) Undo after a delete restores *structure* only, never re-writes overrides — those are already server-sanitized, and re-saving them would double-escape `&`/`<`.

**One-time setup (operator):** set the Supabase secret `EDIT_PASSWORD` (16+ chars) — until then editing and the backoffice are disabled (503) and the public site is unaffected. The buckets `site-content` (public, images) and `bewerbungen` (private, CVs) are auto-created on first use.

## Things that look like problems but aren't

- **`vite.config.ts`'s `figmaAssetResolver`** maps `figma:asset/<file>` to `src/assets/<file>`. `src/assets/` doesn't exist and no source file imports `figma:asset/…` (verified). It's a no-op leftover from the Figma Make scaffold. Safe to ignore; deletion is fine but not necessary.
- **`@source not '../app/components/ui/**'` in `src/styles/tailwind.css`.** Tailwind was generating classes for the 48 dead shadcn files (~60 KB of render-blocking CSS for nothing). The files stay (Figma Make syncs them), their classes don't. **If you ever actually use a shadcn component, that line has to go** or its styles will be missing.
- **[LightPillar.tsx](src/app/components/LightPillar.tsx) (three.js) has no importers.** It's the previous WebGL background, replaced by CSS in `BackgroundScene` after Lighthouse attributed 40.773 ms main-thread and 22.440 ms blocking time to it (WebGL falls back to software rasterisation on weak devices — exactly this audience). Kept as a record; **don't wire it back in**. `three` is still in package.json only because of it.
- **[TerminPage.tsx](src/app/components/TerminPage.tsx) has no importers** while `/termin` is commented out. Not dead code — it's a disabled feature.
- **`default_shadcn_theme.css`** at the repo root is a Figma Make sync artifact (header: `KEEP_IN_SYNC(fullscreen/resources/figmake/shadcn/globals.css)`). It is not part of the Vite build and not referenced by any source file. Don't import it; don't edit it expecting effects on the site.
- **`src/imports/` filenames contain spaces, dots, and parens** (`WhatsApp_Image_2026-04-28_at_11.59.22_(1)-1.jpeg`). They work because Vite handles them; don't rename without updating every import.
- **`pnpm-workspace.yaml` exists** but the project uses npm in practice (`npm i` per README). Don't switch package managers without a real reason.
- **One `npm audit` "high" finding** as of install. Mention to user before running `npm audit fix --force` — the `--force` can pull breaking majors.

## Editing rules I should hold myself to

- **Mobile-first is a hard requirement, not a nice-to-have.** The user explicitly asked me to "beachte auch in Zukunft diese Funktion". For every new UI feature (animation, layout, carousel, 3D scene) ship the mobile variant in the SAME commit, not as a follow-up. Use the existing 768px breakpoint. Patterns established in the codebase: CityRoadmap collapses the SVG snake into a vertical timeline below 768px; BackgroundScene steepens/enlarges its drift layers via media query; GoogleReviews falls back to native swipe scrolling on mobile. Match these — and prefer a **CSS media query over a JS breakpoint** (SSG, see "Pre-rendering").
- **Curved/serpentine motion, not straight lines.** When animating movement (cars, paths, timelines), use Bezier curves. The current EinzugsgebietSection / CityRoadmap is the established pattern.
- **Scroll-driven > time-driven** for movement that tells a story. The car-on-roadmap is tied to scroll progress via the `useScrollProgress` hook in CityRoadmap. Time-based marquees are still fine for ambient looping (PartnerSection, GoogleReviews).
- **Google reviews:** live data comes from `/reviews`; [src/lib/reviews-data.ts](src/lib/reviews-data.ts) is the offline fallback and holds **real** reviews (manually copied 2026-05-12, `isPlaceholder: false`). There is no warning banner any more — the fallback is genuine social proof, just not always-fresh. Keep it that way; if you ever put fake data there, re-add a visible marker.
- **Performance is a feature here, and it was hard-won.** Before changing anything in the render path, read the changelog entries for 2026-07-20/27 in [admin-verwaltung-referenz.md](docs/superpowers/admin-verwaltung-referenz.md) §11. Specifically: don't start a keyframe at `opacity: 0` on the hero (that caused NO_LCP), don't add WebGL, don't put fonts back on Google's CDN, keep images `loading=lazy` except above the fold, and keep the hero `<link rel="preload">` in `index.html` **on one line** (Vite drops a multi-line `imagesrcset`).
- **Stay terse and German on user-facing copy.** Form labels, error messages, button text, headings, alt text — all German. The German copy already exists in `src/imports/Website_Texte.txt` for reference. Ask before adding English UI strings.
- **Don't introduce shadcn `<Button>`/`<Card>`/etc. into existing pages** without converting the surrounding section coherently. Mixed styling reads as a regression.
- **Don't migrate inline `style={jakarta}` to Tailwind classes** (`font-jakarta`) unless I'm also wiring `font-jakarta` through `@theme`/Tailwind config. Mid-migration code is worse than either end state.
- **Don't move the Supabase URL/anonKey** to env vars without coordinating with the user — Figma Make regenerates `utils/supabase/info.tsx`.
- **Phone number consistency:** `05151 7107093` displayed, `tel:+4951517107093` for the link, "Süntelhang 9, 31787 Hameln" for address. In React components use the `shared.*` components (see "Content editor"); the remaining hardcoded copies live in `index.html`'s JSON-LD and in the Edge Function's email templates — grep all of them if this ever changes.
- **Operator notification recipients are configured, not coded** — they come from the `CONTACT_TO`/`JOB_TO`/`APPT_TO`/`MAIL_TO` secrets and fall back to the SMTP mailbox itself. If mail lands in the wrong inbox, that's a secret to change, not a source edit.
- **For UI changes, verify in the running browser**, not just by reading the diff. There's no test suite to catch visual regressions. `npm run build` only catches parse errors — and, since SSG, also crashes at render time (a route that throws is reported as "als Hülle" in the prerender output; **watch for that line**).
- **Log every editor/backoffice/function change** in [admin-verwaltung-referenz.md](docs/superpowers/admin-verwaltung-referenz.md) §11 (date · what · why · files).

Console should be clean — **no warnings at all**, in particular no `[Hydration]` line (that's `main.tsx`'s `onRecoverableError`, which exists precisely to name the mismatching component instead of the useless "React error #418").

Dev does **not** pre-render. To test the real production output:

```bash
npm run build && npx vite preview
```

and check the prerender summary line — currently `prerender: 12 Routen vorab gerendert, 0 als Huelle, 12 Dateien geschrieben.` **The "als Huelle" count must stay 0**; anything else means a route threw during server rendering. `dist/<route>.html` must contain the actual copy, and `dist/404.html` must be the empty shell.

Editor/backoffice changes additionally need a run through `/admin`: login (wrong password → error + throttle), edit a text and an image, Speichern, reload as a normal visitor, then Verlassen and confirm edit mode is really gone after a reload. Server rejection paths can be checked with curl against the deployed function (no password → 401); success paths are the operator's to run, since only they have the password.
