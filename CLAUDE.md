## What this project is

Marketing website for **Cura Doma**, an ambulatory care service (ambulanter Betreuungsdienst) in Hameln, Germany. Single-page React app with multiple routes; all user-facing copy is German. The site exists to (a) explain services covered under §45a/§45b SGB XI to families, (b) capture contact requests, and (c) capture job applications — both via a Supabase Edge Function that emails the operator via Resend.

The whole frontend was originally generated by **Figma Make** and committed largely as-is. That history matters when reading code.

## Quick start

```
npm install
npm run dev      # vite, defaults to http://localhost:5173
npm run build    # vite build → dist/
```

No test runner, no linter, no formatter, no `tsc` step. Vite transpiles TSX via `@vitejs/plugin-react` without type-checking. **There is no `tsconfig.json`** — adding one would be a deliberate change, not a fix. Type errors show up only at runtime (or when an IDE happens to type-check). Treat this as a constraint to work around, not a bug to fix unbidden.

## Stack

- **React 18.3** + **react-router 7** (`createBrowserRouter`, `<Outlet/>`, `<Link/>`)
- **Vite 6** (`vite.config.ts`) with the Tailwind v4 Vite plugin
- **Tailwind CSS v4** — config-less, source globs declared in `src/styles/tailwind.css` via `@source`
- **Radix UI primitives** (full set) and a complete **shadcn/ui** copy under `src/app/components/ui/` — see "shadcn is unused" below
- **Lucide React** for icons (always `strokeWidth={1.5}` in this codebase — match the existing look)
- **Supabase Edge Functions** (Deno + Hono) under `supabase/functions/server/` for the two form endpoints
- **Resend** for transactional email (server-side only; API key lives in Supabase Function env, never in the bundle)

A pile of additional deps (`framer-motion`, `react-hook-form`, `recharts`, `embla-carousel`, `cmdk`, `vaul`, `react-dnd`, `react-slick`, `react-day-picker`, `next-themes`, …) come from the Figma Make starter and are **mostly unused**. Don't assume "if it's in package.json it's wired in." Grep before importing.

## Styling conventions — read before editing any page

The pages were generated by Figma Make and **bypass the design system that was scaffolded alongside them**. Reading the codebase top-down is misleading; here is what's actually true:

1. **Colors are hardcoded hex literals** in arbitrary-value Tailwind classes (`bg-[#6FD3D1]`, `text-[#5F6B73]`, `border-[#E5F4F5]`). Match the existing palette when adding UI:

   | Role                   | Hex        | Where it shows up                                |
   |------------------------|------------|--------------------------------------------------|
   | Brand teal (primary)   | `#6FD3D1`  | CTAs, accent text, icon highlights               |
   | Brand teal (logo)      | `#6FBDB8`  | "Cura Doma" wordmark only                        |
   | Brand teal (hover)     | `#5BC2C0`  | Primary button hover                             |
   | Mint surface           | `#DFF7F8`  | Pills/chips, soft backgrounds                    |
   | Mint border / glow     | `#BFEAF2`  | Borders, blur orbs, selection                    |
   | Card border            | `#E5F4F5`  | Card outlines, dividers                          |
   | Page background        | `#F8FEFF`  | Body                                             |
   | Body text              | `#111111`  | Headings, primary copy                           |
   | Muted text             | `#5F6B73`  | Secondary copy                                   |
   | Tagline / hint         | `#9AA3A8`  | "AMBULANTER BETREUUNGSDIENST", small caps        |

2. **Fonts are set via inline `style` props**, not Tailwind utilities. The pattern is:
   ```tsx
   const jakarta = { fontFamily: "'Plus Jakarta Sans', sans-serif" };
   <h1 style={jakarta}>…</h1>
   ```
   Body text inherits Inter from `Layout.tsx`'s root `<div style={{ fontFamily: "'Inter', sans-serif" }}>`. Lora is used only by the logo. Loaded via Google Fonts in `src/styles/fonts.css`.

3. **`src/styles/theme.css` defines shadcn tokens (`--primary`, `--card`, `--ring`, `oklch(...)`, etc.) — but page code never references them.** It's vestigial. Do not "tidy" pages by switching to `text-primary` etc.; that token currently resolves to `#030213` (near-black), which would visibly break the design. Either leave the token wall intact, or change it deliberately and migrate the whole site at once. Don't half-migrate.

4. **`src/app/components/ui/` is a complete shadcn/ui drop-in (`button.tsx`, `card.tsx`, `dialog.tsx`, … 40+ files) — and nothing in `src/app/components/*Page.tsx` imports from it.** Pages use raw `<button>`/`<div>` + Tailwind. Before reaching for `<Button variant="…">`, decide: do I want to introduce shadcn here (and accept it'll look out of place against hand-rolled buttons), or stay consistent with the rest of the page? Default to **stay consistent**.

5. **Animations** live as inline `<style>{`@keyframes …`}</style>` blocks at the bottom of components, named with a `cura` prefix (`curaPartnerMarquee`, `curaFadeIn`). Tailwind classes reference them via `motion-safe:animate-[curaFadeIn_900ms_ease-out_both]`. Keep the prefix to avoid collisions.

6. **Lucide icons** use light strokes — `strokeWidth={1.5}` in the vast majority of cases, and `1`–`1.3` for a handful of large decorative icons (e.g. [DemenzPage.tsx:147](src/app/components/DemenzPage.tsx#L147), [EntlastungPage.tsx:162](src/app/components/EntlastungPage.tsx#L162)). Default Lucide is 2 and looks heavier than the rest of the UI — match neighbouring icons rather than picking arbitrarily.

## TypeScript: there is no tsconfig

`.tsx` files are transpiled by Vite's esbuild without type-checking. There is no `tsc` step in `package.json`. Two consequences:

- A change that breaks types will **build and run**; you'll only catch it when the page errors at runtime or your editor flags it. Verify by exercising the route in the browser, not by running `tsc`.
- Don't be surprised by absolute-looking imports such as `from "/utils/supabase/info"` (the leading slash makes it a Vite-resolved root-relative path, working because Vite's project root is the repo root). Both [src/app/components/KontaktPage.tsx:4](src/app/components/KontaktPage.tsx#L4) and [src/app/components/KarrierePage.tsx:4](src/app/components/KarrierePage.tsx#L4) use it. The autogenerated comment on `utils/supabase/info.tsx` says DO NOT EDIT — leave the path style alone unless changing both call sites.

The `@` → `src` alias is configured in `vite.config.ts` but not currently used in source. Either style is fine; match nearby code.

## Backend (Supabase Edge Function + Resend)

Single function under [supabase/functions/server/index.ts](supabase/functions/server/index.ts), deployed to:

```
https://${projectId}.supabase.co/functions/v1/make-server-ec6100a6/<route>
```

Routes:

- `GET  /health` → `{status:"ok"}`
- `POST /contact-messages` — body: `{name, email, phone?, subject?, message, page_source?, consent_privacy}`. Stores under `contact_message:<uuid>` in `kv_store_ec6100a6`, then emails `info@curadoma.de` via Resend. Validation returns `422 {error, fields}` with German field-level messages.
- `POST /job-applications` — body: career form fields. Stores under `job_application:<uuid>`, emails `Tolunay.u@outlook.de`. **Note:** the CV file is *not* uploaded — only its filename is sent. The user-facing form lets the applicant pick a file, but the bytes are dropped client-side. Both the email body and the autoreply mention this. If asked to "make CV upload work," that's a real feature request, not a bug.
- `GET  /reviews` — returns `{reviews, rating, total, placeUrl, cached, stale}`. Two-stage Google Places call: first `findplacefromtext` to resolve the Place ID from the hardcoded business address (`PLACE_DISCOVERY_QUERY = "Cura Doma Süntelhang 9 31787 Hameln"`), cached 7 days under `discovered_place_id`; then `place/details` for reviews, cached 6h under `cache:reviews:<placeId>`. Returns `503 {missing: [...]}` only when `GOOGLE_PLACES_API_KEY` is absent. `GOOGLE_PLACE_ID` is supported as an optional override if auto-discovery picks the wrong listing. Google caps reviews at 5 per call — upstream limit, not ours.
- `GET  /instagram-posts` — returns `{posts, cached, stale}`. Calls Instagram Graph API `v18.0/{ig-id}/media`; cached 30 min in KV. Returns `503 {missing: [...]}` when `INSTAGRAM_ACCESS_TOKEN` or `INSTAGRAM_BUSINESS_ACCOUNT_ID` secret is absent. Long-lived tokens last 60 days — refresh via the Graph API before expiry.

Cache pattern (`cachedFetch<T>` helper in [index.ts](supabase/functions/server/index.ts)): get from KV → if fresh return → else hit upstream → write to KV → return. On upstream failure with a stale cache: serve the stale cache and flag `stale: true`. On failure with no cache: return 502.

Auth model: anonymous clients call POST with the public anon key in `Authorization: Bearer …`. Reading/updating/deleting rows requires the service role key, which lives only in the Function env (`SUPABASE_SERVICE_ROLE_KEY`). The frontend never gets a service-role key.

Email sender:
- Sender defaults to `Cura Doma <onboarding@resend.dev>` (Resend's shared dev sender) until `RESEND_FROM` is set on a verified domain.
- `RESEND_API_KEY` is required; without it the endpoint still returns `201` and stores the row, but `email_sent: false` comes back in the response. Don't treat that as a bug-in-code — it's a config issue.

Required Supabase Edge Function secrets (set in Supabase Dashboard → Edge Functions → server → Secrets):
- `RESEND_API_KEY` — transactional email (contact + job application notifications)
- `RESEND_FROM` *(optional)* — verified sender address, defaults to Resend's shared dev sender
- `GOOGLE_PLACES_API_KEY` — server-side API key with Places API enabled (Find Place + Place Details)
- `GOOGLE_PLACE_ID` *(optional)* — Place ID override; only set if auto-discovery picks the wrong listing
- `INSTAGRAM_ACCESS_TOKEN` — long-lived Page access token (Meta Graph API; 60-day TTL)
- `INSTAGRAM_BUSINESS_ACCOUNT_ID` — numeric IG Business/Creator account ID

If any of these are missing, the relevant endpoint returns `503 {missing: [...]}`. The frontend handles the cases gracefully — `GoogleReviews` falls back to `src/lib/reviews-data.ts` placeholders + a warning banner; `InstagramFeed` hides itself entirely.

The committed `utils/supabase/info.tsx` carries `projectId` + the **anon** key. That is intentional and safe (anon keys are designed to be client-visible). Do not move it to env vars — Figma Make regenerates this file, and breaking the contract will lose changes on the next pull.

The form pages submit `fetch(...)` directly. They show a success state on `2xx`, surface `data.fields` as inline field errors on `422`, and a German fallback message otherwise. Match this pattern for any new form.

## Things that look like problems but aren't

- **`vite.config.ts`'s `figmaAssetResolver`** maps `figma:asset/<file>` to `src/assets/<file>`. `src/assets/` doesn't exist and no source file imports `figma:asset/…` (verified). It's a no-op leftover from the Figma Make scaffold. Safe to ignore; deletion is fine but not necessary.
- **`favicon.ico` 404** in dev console. No favicon is shipped. Add one if asked, otherwise leave it.
- **`src/styles/globals.css` is empty and not imported anywhere.** Pure scaffold residue. Safe to delete; safe to leave.
- **`default_shadcn_theme.css`** at the repo root is a Figma Make sync artifact (header: `KEEP_IN_SYNC(fullscreen/resources/figmake/shadcn/globals.css)`). It is not part of the Vite build and not referenced by any source file. Don't import it; don't edit it expecting effects on the site.
- **`src/imports/` filenames contain spaces, dots, and parens** (`WhatsApp_Image_2026-04-28_at_11.59.22_(1)-1.jpeg`). They work because Vite handles them; don't rename without updating every import.
- **`pnpm-workspace.yaml` exists** but the project uses npm in practice (`npm i` per README). Don't switch package managers without a real reason.
- **One `npm audit` "high" finding** as of install. Mention to user before running `npm audit fix --force` — the `--force` can pull breaking majors.

## Editing rules I should hold myself to

- **Mobile-first is a hard requirement, not a nice-to-have.** The user explicitly asked me to "beachte auch in Zukunft diese Funktion". For every new UI feature (animation, layout, carousel, 3D scene) ship the mobile variant in the SAME commit, not as a follow-up. Use the existing 768px breakpoint. Patterns established in the codebase: CityRoadmap collapses the SVG snake into a vertical timeline below 768px; BackgroundScene reduces orb count + blur radius on mobile; GoogleReviews falls back to native swipe scrolling on mobile. Match these.
- **Curved/serpentine motion, not straight lines.** When animating movement (cars, paths, timelines), use Bezier curves. The current EinzugsgebietSection / CityRoadmap is the established pattern.
- **Scroll-driven > time-driven** for movement that tells a story. The car-on-roadmap is tied to scroll progress via the `useScrollProgress` hook in CityRoadmap. Time-based marquees are still fine for ambient looping (PartnerSection, GoogleReviews).
- **Google reviews:** the home-page review section reads from [src/lib/reviews-data.ts](src/lib/reviews-data.ts), which currently ships placeholder data flagged with `isPlaceholder: true`. A warning banner shows in the UI as long as any review carries that flag. Real reviews must be pasted into that file (or hooked up via Places API + a new `/reviews` Edge Function route — see the file's top comment).
- **Stay terse and German on user-facing copy.** Form labels, error messages, button text, headings, alt text — all German. The German copy already exists in `src/imports/Website_Texte.txt` for reference. Ask before adding English UI strings.
- **Don't introduce shadcn `<Button>`/`<Card>`/etc. into existing pages** without converting the surrounding section coherently. Mixed styling reads as a regression.
- **Don't migrate inline `style={jakarta}` to Tailwind classes** (`font-jakarta`) unless I'm also wiring `font-jakarta` through `@theme`/Tailwind config. Mid-migration code is worse than either end state.
- **Don't move the Supabase URL/anonKey** to env vars without coordinating with the user — Figma Make regenerates `utils/supabase/info.tsx`.
- **Phone number consistency:** `05151 7107093` displayed, `tel:+4951517107093` for the link, "Süntelhang 9, 31787 Hameln" for address. These appear in multiple files; if changing, grep for all of them.
- **Two operator emails are different on purpose:** contact form → `info@curadoma.de`, job applications → `Tolunay.u@outlook.de`. Don't unify them.
- **For UI changes, verify in the running browser**, not just by reading the diff. There's no test suite to catch visual regressions.

## Verifying changes locally

The dev server is at `http://localhost:5173`. Quick smoke-test path covering the failure-prone surface:

1. `/` — hero loads, partner marquee animates, GoogleReviews scrolls (placeholder banner shows), Einzugsgebiet section's two snake routes render with cars at the start of each route.
2. Scroll slowly through `/` past the Einzugsgebiet section: both cars should advance along their serpentine paths, lighting up stops as they pass.
3. `/leistungen` and at least one sub-page (`/entlastung`).
4. `/kontakt` — fill form, submit. Validation catches bad inputs; submit with valid input goes to the Edge Function (with no backend env: expect an error toast, verify the form re-enables).
5. `/karriere` — same.
6. Mobile-width (DevTools 375×812) — burger menu opens, dropdowns work, footer collapses, **CityRoadmap shows as vertical timeline (not the SVG snake)**, **GoogleReviews scrolls horizontally with swipe**.

Console should be clean except for the `favicon.ico` 404.

## When in doubt

If a change involves: secrets, the Supabase function URL, the anon-key file, removing dependencies, regenerating Figma Make output, or changing route slugs — **ask first**. Everything else (copy edits, new sections, palette-consistent components, fixing form UX) is fair game.
